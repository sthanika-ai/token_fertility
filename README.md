# FLORES+ Tokenizer Fertility Benchmark

Measures how many tokens each model's tokenizer needs for the same sentence in English, Hindi, Telugu, Kannada and Marathi, and translates that into serving cost.

## What it measures

The corpus is the full FLORES+ devtest split: 1,012 sentence-aligned rows, professionally translated. For every (model, language, sentence) it records:

- `token_count`: tokens the model's tokenizer produces for that sentence
- `fertility_tokens_per_word`: tokens per word (lower is more efficient for that language)
- `chars_per_token`: characters represented per token
- `parity_vs_english`: this sentence's token count divided by its English counterpart's (meaningful because FLORES+ is a genuine parallel corpus)
- `est_input_cost_usd` and `cost_usd_per_1m_chars`: cost from a dated pricing table, null for open-weight models with no owner-published API price

Corpus-level parity and fertility are total tokens over all 1,012 sentences, not an average of per-sentence ratios. Every number comes from tokenizing locally or from a free `count_tokens`-style call, so nothing here generates text or spends money. Report: [sthanika.ai](https://sthanika.ai/research/tokenizer-fertility-2026)

## Quickstart

```bash
git clone https://github.com/sthanika-ai/token_fertility.git
cd token_fertility
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -e .

# fetch the corpus (no HF token needed, despite the Hub UI showing it as gated)
python flores_build_corpus.py      # -> flores_subset/corpus_flores_v1.json

# local tokenizers: a few minutes (list all ten in one command; each run overwrites results.csv in --out)
python flores_fertility.py --models sarvam-1,gemma-2-9b,gemma-3-4b,brahmic-131k,mistral-nemo-tekken,qwen3-8b,llama-3.1-8b,cl100k-base,gpt-4o,sarvam-30b

# merge into flores_summary/summary.csv and summary.json
python flores_merge_report.py --out flores_summary
```

Live-API models, run one at a time, not in parallel. Each is about 5,060 calls against a free rate-limited endpoint (roughly 1–1.5 h per Claude model, up to about 6 h for Gemini). Counts are cached per sentence, so an interrupted run resumes where it stopped.

```bash
python flores_fertility.py --models claude-sonnet-4-5 --cache-dir cache_live_sonnet45 --out flores_results_sonnet45
python flores_fertility.py --models claude-opus-4-8   --cache-dir cache_live_opus48   --out flores_results_opus48
python flores_fertility.py --models gemini-3.6-flash  --cache-dir cache_live_gemini36 --out flores_results_gemini36
```

Notes:

- **Credentials.** Gated tokenizers (Llama 3.1 8B, Gemma 2 9B, Gemma 3 4B) need `HF_TOKEN` with the model licenses accepted. Live-API models need `GEMINI_API_KEY` ([free](https://aistudio.google.com/apikey)) and/or `ANTHROPIC_API_KEY`. All other models need no auth.
- **Reproducibility.** Local counts are deterministic with `requirements.txt` pinned, so a diff between runs means a dependency changed a tokenizer's behaviour. Live-API counts carry no such guarantee. `pip install -e .` alone also works but uses the `>=` bounds in `pyproject.toml`.
- **Read live-API numbers from `flores_summary/`.** Raw live-API counts include per-request overhead (8 tokens for Claude Sonnet 4.5, 7 for Claude Opus 4.8, 2 for Gemini 3.6 Flash) that `flores_merge_report.py` corrects for. Do not hand-average the raw `flores_results*/results.csv` files.
- **Extending it.** To add a language, edit `LANG_CODES` in `flores_build_corpus.py`, rebuild, and bump `CORPUS_VERSION`. To add a model, add a `ModelSpec` to `src/tokfertility/registry.py` and a pricing row (and, for a local tokenizer, to `DEFAULT_MODELS`/`LOCAL_MODELS` in `flores_fertility.py`). To update pricing, add a new `data/pricing_YYYY-MM-DD.json` and pass it with `--pricing` rather than editing an existing file.

## Results

Result tables, token caches and the corpus are generated by the scripts above, not committed. After a run, the merged comparable table is in `flores_summary/`. Full results and analysis: [sthanika.ai](https://sthanika.ai/research/tokenizer-fertility-2026)

Caveats when reading them:

- Tokens per whitespace-separated word is a proxy, not a linguistically precise unit, because all four Indic languages are more agglutinative than English.
- Llama, Gemma, Qwen, Mistral and Sarvam have no single official API price, so their cost columns are null.
- Corpus-level parity is what predicts a serving bill. Averaging per-sentence ratios over-weights short sentences, where the ratio is noisiest.
- Pricing snapshots go stale fast. `data/pricing_2026-08-17.json` is the latest bundled, so re-verify against each provider's current pricing before citing a cost.
